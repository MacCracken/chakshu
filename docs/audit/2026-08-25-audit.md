# chakshu — security & hardening audit, v0.9.3 → v0.9.4

**Verdict: PASS.** Every confirmed finding is fixed and gated in v0.9.4.

**Scope:** the four surfaces that shipped *after* the v0.7.13 P-1 sweep and had never been
audited — `--watch` NDJSON ingest (v0.8.0), GPU sysfs telemetry (v0.9.1), the AGNOS Set-1
scancode decoder (v0.9.3), and the `--with-logs` / AI prompt path (v0.8.1, hardened v0.8.2).
The prior artifact, [`p1-sweep-findings.md`](../development/p1-sweep-findings.md), was stamped
v0.7.13, carried no PASS verdict, and sat outside the mandated `docs/audit/` path.

**Method:** four independent auditors, one per surface, each required to produce a
`file:line` and a runnable reproduction. Every finding was then handed to a separate
adversarial verifier instructed to **refute** it and to default to "refuted" when uncertain.
Only findings a verifier personally reproduced against the shipped binary are recorded below.

**Result: 38 raised, 14 confirmed, 24 refuted.** The refutation rate is the point — a false
finding in a v1.0 audit burns the reader's trust in every other line.

| Surface | Raised | Confirmed |
|---|---|---|
| `--watch` NDJSON ingest | 12 | 6 |
| `--with-logs` / AI prompt | 13 | 5 |
| AGNOS scancode input | 9 | 3 |
| GPU sysfs telemetry | 4 | **0** |

## The two that mattered most

### W1 — a security monitor silently dropping security events (HIGH)

`--watch` carried partial records in a 512-byte buffer against a 4096-byte read window. A
record straddling a read boundary was not truncated, it was **erased**: `_watch_off` had
already advanced past the bytes, so the event never entered the ring, the counter never
incremented, and nothing was printed. Records too long to fit one window were lost
unconditionally.

**Measured loss: 71 of 300 records (23.7%)** on a realistic mixed-size stream. The
CHANGELOG asserted the opposite — *"Partial records are carried, not dropped"* — and has
been corrected.

This is the worst possible failure direction for this feature: silence in a security
monitor reads as *"nothing happened"*, which is a lie in the quiet direction. An attacker
does not even need write access — aegis embeds attacker-chosen strings (file paths, rule
names) in `description`, so triggering a detection on a long path influences whether that
detection is displayed.

**Fixed:** carry buffer 512 B → 4096 B (≥ the read window), so the straddle class is gone;
records longer than any window are skipped **and counted**, with the count surfaced in both
the dump and the panel. Note the naive fix is wrong — simply enlarging the carry drives the
next read window to zero and *stalls* the stream; and the old `rem > 512` clamp was not
gratuitous, it was the only bound on the copy, so it was raised rather than removed.

### A1 — `$CHAKSHU_LOG_PATH` put the process environment on the wire (HIGH)

The path was passed to the reader with no validation, so `CHAKSHU_LOG_PATH=/proc/self/environ`
folded every environment variable — every token and credential in it — into the prompt sent
to hoosh. That is a direct breach of CLAUDE.md's one binding rule: *no /home contents, no env
vars.*

A first fix in this cycle applied a string-prefix denylist and **was itself insufficient** —
a symlink, a doubled slash (`//proc/...`) and a relative path (`../../proc/...`) each defeated
it and still reached the file. Recorded because the incomplete fix is the more instructive
half.

⚠ A type check alone does not help either: `/proc/self/environ` reports **`S_IFREG`**.

**Fixed:** open with `O_NOFOLLOW|O_NONBLOCK`, `fstat` **that fd** (no second lookup — this
also closes the TOCTOU window, A9), resolve what was actually opened via `/proc/self/fd/<n>`,
and apply the denylist to the canonical answer. All four bypass vectors are now gated in
`tests/with_logs_smoke.py`.

Also fixed in this cycle, found before the audit: `--explain` returned from mid-loop so it was
the one path that never validated the rest of the command line; `_ag_shift` latched with no
resync, making the AGNOS TUI **unquittable** after one lost break byte; `_ag_drain` trusted the
kernel's returned count with no upper clamp, decoding stack residue into keystrokes.

## GPU telemetry: clean

Four findings raised, **none survived verification**. The `0x`-prefix parse bug fixed at
v0.9.1 is complete, path assembly is bounded, and failed sysfs reads degrade rather than
being treated as data.

## Known gaps, stated rather than hidden

- **W12 (open).** The AI prompt's "recent anomalies" section cannot currently be reached —
  `?` explains a *pid*, and watch mode has no selection index. Either wire it or remove it;
  leaving it is a section that reads as covered and is not.
- **Unkeyed high-entropy secrets with no recognisable prefix.** A length-or-entropy rule was
  considered and **rejected**: it blanks git SHAs, UUIDs, content hashes and long paths — the
  ordinary content of the logs this feature exists to show. This cycle demonstrated that
  failure mode in miniature when general filler words in the lookback blanked "deploy". A
  redactor that destroys the context is not safer, only useless more quietly.
- **Display width.** Clipping is by bytes, not columns. A CJK glyph is 3 bytes and 2 columns,
  so a CJK row under-fills its line. The corruption is fixed; the width problem needs a table
  the lean build deliberately does not link.
- **Rotation identity is approximated by size.** The stdlib exposes `STAT_MODE`/`STAT_SIZE`
  only — no portable `STAT_INO`/`STAT_DEV` — so a replacement log of byte-identical length is
  missed, and self-corrects on the next append.

## Gates added this cycle

- `tests/literal_len_check.py` — decodes every `syscall(1, fd, "…", N)` literal and compares
  its byte length to the declared count. **The highest bug-finding-power item the P-1 sweep
  specified, and never built until now.** It found all three shipping defects immediately.
  Wired into CI.
- `tests/with_logs_smoke.py` — grew to 13 secret shapes, 4 path-bypass vectors, and an
  **over-redaction** half. That last one matters: a redactor tuned too aggressively passes
  every leak test while destroying the context, and nothing else would notice.
- `scripts/smoke.sh` — 23 → 25 gates, including `--version` vs the `VERSION` file, which
  catches a stale build that would otherwise pass every other gate here.
- `.github/workflows/ci.yml` — an `--agnos` compile gate. That build was the only unguarded
  one in the project, and it is the one the v1.0 milestone is named after.
